# Devanagari rendering proof (`fonts.md`)

Brief §5.1 and design §6.5 require the two Devanagari faces to be verified in the real browser, not by glyph tables
alone. This note records the FEAT-103 run of `tools/audit.py` over `dist/_dev/fonts.html` (built from
`assets/dev/fonts.html`), the shots a human read, and the subsetting facts from `fonts/README.md`.

## Run

```
c:\Users\sudiskmr\Downloads\DomainClassification\.venv\Scripts\python.exe tools\audit.py --pages /_dev/fonts.html --widths 390,1440 --themes light,dark --checks UI-22 --prefix feat103-fonts-r2 --detail "p[data-test=gayatri]","p[data-test=vedicext]"
```

- Browser: Microsoft Edge (Chromium, Playwright 1.55 `channel="msedge"`, headless, `--disable-lcd-text`), Windows,
  2026-11-01. Device scale factor 1, `prefers-reduced-motion: reduce`.
- UI-22 result: **PASS at 390 and 1440, light and dark** — 48 rendered strings (12 test strings × 2 faces × 17/23 px).
  For every string `document.fonts.check('<size> "<face>"', text)` is true **and** `canvas.measureText` in the named
  face differs from the generic fallback (`serif` for Tiro Devanagari Sanskrit, `sans-serif` for Noto Sans Devanagari),
  which is the design-review NIT 10 correction (`fonts.check()` alone is true whenever no face would be needed).
- Report: `dist/_reports/audit-feat103-fonts-r2.json` (regenerated by every run; not committed).

## Subsetting (from `fonts/README.md`, FEAT-101, fontTools 4.59.2)

- Noto statics cut from the variable files with `fontTools.varLib.instancer.instantiateVariableFont(font, {"wdth": 100, "wght": 400 | 600}, updateFontNames=True)`.
- Every face subset with `pyftsubset <src> --output-file=<out>.woff2 --flavor=woff2 --unicodes=<ranges> --name-IDs='*' --name-languages='*' --layout-features='*' --notdef-outline --glyph-names --recommended-glyphs --no-hinting`.
- Unicode ranges: Tiro `U+0900-097F,U+1CD0-1CFF,U+A8E0-A8FF,U+200C-200D,U+0964-0965,U+093D,U+0020-007E,U+00A0-00FF,U+0100-017F,U+1E00-1EFF,U+2018-2019,U+02BC,U+0304,U+0323`; Noto Sans Devanagari `U+0900-097F,U+1CD0-1CFF,U+A8E0-A8FF,U+200C-200D,U+0964-0965,U+093D,U+0020-007E`; Noto Sans `U+0020-007E,U+00A0-00FF,U+0100-017F,U+2000-206F,U+20B9`.
- Sizes: Tiro 138,140 B · Noto Sans Devanagari 53,860 / 57,312 B · Noto Sans 25,588 / 26,544 B · total 301,444 B (≤ 450 KB budget, design §23).
- Loading on real pages (UI-23, measured by the same tool on `/hi/`, `/404.html`, `/hi/offline/`): all five `@font-face` rules carry `font-display: optional`, the two preloads (Noto Sans Devanagari 400, Tiro 400) are in `<head>`, all five faces reach `status=loaded` from `BASE_PATH/fonts/` on a warm load, zero cross-origin requests.

## Known gaps (unchanged from FEAT-101)

- Tiro lacks U+0953, U+0954 (→ Noto Sans Devanagari), ḹ U+1E39 (→ Noto Sans) and U+A8FE/U+A8FF; the gate counts U+0953/0954 and the build counts ḹ.
- The dev page itself does not join dandas to the preceding word, so its long lines show orphan `॥ ३ ॥` — intentional: it is a glyph test, not a layout test. Real pages are checked by UI-28.
